Aloe Language Spec (Draft, English)

edit-version: 159
edit-date: 2026-10-22T11:02:13+09:00

This document is an English draft based on the upstream specification.
In addition, it introduces a reference validity model using valid / invalid and removes null from the specification.
It also includes an extension to 4.2 with-blocks: type-based with (for class/struct/enum) as a shorthand for static members / enumerators.
Furthermore, it introduces the universal type object and box objects, implicit unbox casts, and the unbox operator.
Other parts are kept as faithful as possible to the upstream.

0. Overview

Aloe is a statically typed scripting language aiming for simple and intuitive syntax.
It runs on a stack-based virtual machine (AloeVM) and targets the following goals.

  • Readable and writable for education and small applications
  • Runs on the C# runtime and WebAssembly (WASM) environments
  • Controls I/O and concurrency while remaining statically typed via pipe and filter

Features:

  • Static typing
    • Type inference via var
    • Explicit typing via let
  • Value types / reference types
    • struct ... value type
    • class / object ... reference type
  • GC-based memory management (exact algorithm is VM-implementation-defined)
  • Reference invalid state (invalid) as a language-level model
    • delete invalidates a reference variable; accessing members afterward throws an exception.
    • invalid is not assignable (for validity checks only).
  • Universal reference type object and boxing / unboxing via box objects
  • Dataflow-style design via pipe / filter

1. Basic Syntax

1.1 Comments

// single-line comment




/* multi-line
   comment */

struct Point { field x: int; field y: int; method sum(offset: int): int { return this.x + this.y + offset; } }
function measure(point: Point): int { return point.sum(1); }
  • From // to end of line is a line comment.
  • /* to */ is a block comment.
  • Block comments are not nested: the comment starts at the first /* and ends at the first following */.
    Any additional /* or */ tokens inside are treated as part of the comment.

1.2 Identifiers

  • Allowed characters: ASCII letters (A-Z, a-z), digits (0-9), underscore _
  • The first character must be a letter or _.
  • Identifiers are case-sensitive.
  • Keywords cannot be used as identifiers.
  • A standalone _ is not a valid identifier. Underscores remain allowed inside identifiers such as _name and foo_bar.
  • Unicode characters may be used (excluding whitespace and separators).

1.4 Literals

1.5 Statement terminator

var x = 10;
x = x + 1;
print(x);
  • All statements must end with a semicolon ;.
  • There is no automatic semicolon insertion.

1.5.1 Function completion

  • A non-void function must return a value on every path that can complete normally.
  • A literal while (true) loop with no reachable break cannot complete normally. A reachable break allows the loop to finish, so the function must still return a value on any path that continues afterward.
  • For loop-exit analysis, a break in an unreachable branch is ignored. For example, a break inside if (false) does not make while (true) fall through.

1.6 Whitespace

  • Spaces, tabs, and newlines separate tokens.
  • Consecutive whitespace is treated as a single separator.
  • Indentation has no semantic meaning.

1.7 Case sensitivity

  • Identifiers and keywords are case-sensitive.
  • All keywords are lowercase except Result.

2. Type System

2.1 Primitive types

Aloe defines the following 8 primitive types.

  • bool / boolean - boolean value.
  • int / integer - signed integer.
  • float - floating point number.
  • decimal - high precision decimal number.
  • string - string (internally Unicode).
  • byte - unsigned integer 0-255.
  • char - a single character.
  • void - no return value (return-only type).

valid / invalid are not types. They are special constants (literals) for checking reference validity.
null is removed from the specification; invalid references are modeled via invalid.

2.2 Composite / user-defined types

  • Arrays: T[]
  • Lists: T()
  • Sets: T{}
  • Maps: map<T> or map<K/V>
  • struct
  • class
  • enum, bitfield enum
  • Async tasks: task
  • Universal reference: object
  • Pipes: pipe<T> (see Chapter 18)
  • Result type: Result<T> (see Chapter 18)

2.3 Value types / reference types

  • Value types:
    • int, float, decimal, bool, byte, char
    • struct
    • enum, bitfield enum (internal representation is int32)
  • Reference types:
    • class
    • string (implementation-wise a reference type)
    • object
    • task, pipe<T>, Result<T>, etc.

object type

  • object is a special reference type that can hold any value except void.
  • Any reference-typed value can be implicitly assigned to object (reference copy).
  • Assigning a primitive value to object performs boxing into the corresponding box object (see 2.4).
  • There is no implicit conversion from object to a concrete type (use as or implicit unbox casts).
  • The current compiler tracks local interface facts inside an if branch or while body. Positive x is T tests may be parenthesized and joined by and; or retains only facts guaranteed by every branch, joining targets to their unique most-specific common interface ancestor, including siblings and diamonds. Direct body assignments use the original declared type and clear temporary narrowing afterward; direct delete/consuming unbox also clear it. Earlier reads remain narrowed, while later reads require a fresh test or cast unless the declared type already provides the member. Nested if/else-if branches now preserve earlier and sibling reads. At a join, incoming facts survive only if every fallthrough path preserves them; writes on non-rejoining return, rethrow and proven non-fallthrough paths do not invalidate the surviving path. Single-pass with blocks preserve incoming facts until writes; captured class/named-box targets remain independent of the original local. Synchronous try/catch preserves facts until writes, discards facts for possibly written slots at catch entry, and merges only fallthrough outcomes. A direct top-level local declaration initializer or assignment to an already declared local whose right-hand side, optionally wrapped in parentheses, is a (possibly parenthesized) signed integer literal divided or remaindered by an (optionally parenthesized) integer literal zero is treated as a guaranteed exceptional edge; later statements are unreachable and do not affect catch-entry facts. If only one try/catch path falls through, facts from that path continue; if both fall through, only facts common to both are retained. While/foreach entry now discards incoming facts for locals possibly written in the header/body. Earlier reads outside the loop remain narrowed; while conditions may re-establish body facts each iteration, including nested conditional/with/try writes. Negation flips the selected truth branch, and an explicit else block uses facts guaranteed when its condition is false. Outer false-branch facts apply to else-if conditions and branches, with separate branch states and write invalidation at their joins. An if/else joins both continuing branches through a unique most-specific common interface, or exports the final facts of its sole continuing branch, while a no-else exit guard applies guaranteed positive false-condition facts; ambiguous/no-common-ancestor joins and interface intersections remain unsupported.

Struct restrictions and copying

  • Struct fields may only be primitives and other structs.
  • Reference-typed fields (e.g., classes) are not allowed.
  • Struct assignment always copies by value.
  • No max-size limit is defined by the spec.

Class vs struct

  • A class may have struct fields.
  • Assigning a class instance to another variable copies the reference (the object is shared).

2.4 boxing / unboxing (box objects and ToXxx)

Boxing/nonconsuming-unboxing prototype (2026-10-13): int, byte, char, float, decimal, string and bool/boolean values box when assigned/passed/returned to generic object, used in typed object[] elements/writes, or explicitly cast as object. Each boxing allocates a fresh heap identity; existing reference assignment shares its handle. Inferred primitive arrays retain their primitive element type. A matching live box can be extracted using as P or an expected primitive assignment/argument/return/array-element/index context, including a primitive cast fallback. Extraction preserves the primitive payload and does not consume or mutate the box reference. Wrong kinds, dead references, bad box shape/payload or numeric conversion fail with InvalidCastException; ifnot remains lazy. Box payloads are initialized Committed values even during Tick/getter allocation and have no source mutation API. Getter extraction reads Committed payloads; caller extraction reads current payloads. Existing array/class/queue roots retain boxes through GC. String payloads remain managed immutable strings, with no heap Object edges. Runtime names box:int, box:string and corresponding canonical primitive names are reserved one-field descriptors; raw callers must supply valid shape/kind/domain and descriptors are not authenticity protection. Enum/struct/pipe values do not box. Named box types/constructors/ToXxx are described below; Operator/condition unboxing is described in section 5.2.2; direct WASM remains unsupported. See the boxing decision. This example executes after AloeBC round-trip.
Named box prototype (2026-10-13): builtin reference types Integer, Byte, Char, Float, Decimal, String and Boolean support exactly one corresponding primitive constructor argument and zero-argument ToInt/ToByte/ToChar/ToFloat/ToDecimal/ToString/ToBool extraction. Construction allocates a fresh existing box; matching primitive assignments/parameters/returns box automatically and reference aliases preserve identity. Generic object references require as Integer etc to recover the named type. Primitive-to-named-box casts box the original kind then check it; incompatible kinds throw InvalidCastException or evaluate ifnot lazily, without numeric conversion. Extraction validates a live one-field matching box and preserves its primitive payload without consuming the reference. All seven type names are reserved for class/enum/struct declarations; rename conflicting user-defined types. Inheriting boxes, private payload properties/setters and other ToXxx members are unsupported. Named box arrays support literals, empty contexts, indexing/writes/Length/foreach and nested jagged arrays with existing GC/Tick rules. They are invariant and use exact runtime descriptors box:int[], box:string[] etc, with one [] per level. Named Byte reference contexts require a byte value; use new Byte(255) for the existing byte constructor literal context. No new syscall/opcode/codec format is added. Operator/condition unboxing is described in section 5.2.2; direct WASM remains unsupported. See the named-box decision. This example executes after AloeBC round-trip.
function identity(value: Integer): Integer { return value; }
function main(args: string[]): int {
    let number: Integer = 42;
    let opaque: object = identity(number);
    var recovered = opaque as Integer;
    var explicitBox = new Integer(42);
    if (recovered == number and explicitBox != number and recovered.ToInt() == 42) { return 42; }
    return 0;
}
Named-box with prototype (2026-10-13): with accepts expressions statically typed as Integer, Byte, Char, Float, Decimal, String or Boolean, including constructors, function/property results, indexed elements and explicit named casts. Each target is evaluated once from left to right and retained in a rooted temporary local. Its matching zero-argument .ToXxx() can be used in value expressions; extraction is nonconsuming and preserves the exact primitive kind and existing live-reference/box-shape/payload checks. Reassigning or deleting the original variable does not change the captured target. Multiple targets can mix boxes with existing class/enum/struct targets; duplicate member candidates within one block are ambiguous, while inner blocks take priority and restore the outer context on exit. No bare ToXxx shorthand is added. Private payloads, setters, ignored extraction results, bare box type targets and statically opaque object targets are rejected. Cast an opaque object to its named box type first. Invalid captured references fail with InvalidReferenceException when a member is read; an unused invalid target alone does not dereference it. Tick/getter extraction and GC use existing rules; no new syscall, opcode or codec layout is introduced. Operator/condition unboxing is described in section 5.2.2; direct WASM remains unsupported. See the box-with decision. This example returns 42 after AloeBC round-trip.
function main(args: string[]): int {
    var number = new Integer(42);
    with (number) {
        number = new Integer(7);
        return .ToInt();
    }
}
function identity(value: object): object { return value; }
function main(args: string[]): int {
    let boxed: object = 42;
    var alias = identity(boxed);
    let values: object[] = [boxed, "Aloe", true];
    let first: int = values[0];
    var second = alias as int;
    if (boxed == alias and first == 42 and second == 42 and (values[1] as string) == "Aloe" and (values[2] as bool)) { return 42; }
    return 0;
}

Aloe defines a box object class for each primitive type in order to store primitives inside object. A box object name starts with an uppercase letter and derives from object.

  • bool / boolean - Boolean
  • int / integer - Integer
  • float - Float
  • decimal - Decimal
  • string - String
  • byte - Byte
  • char - Char
  • A box object stores the corresponding value internally, but it does not expose a public value property (value is private).
  • Unboxing is performed via the corresponding ToXxx() method.
  • Canonical ToXxx() names are:
    • ToBool(), ToInt(), ToFloat(), ToDecimal(), ToString(), ToByte(), ToChar()
  • Boxing: assigning a primitive to object stores an instance of the corresponding box object.
  • Unboxing: extracting a primitive from object uses as, implicit unbox casts, or the unbox operator.

3. Numbers & Conversions

3.1 int and float

  • Expressions mixing int and float result in float.
    • int + float -> float
    • int - float -> float
    • int * float -> float
    • int / float -> float

3.2 decimal

  • decimal is a high-precision decimal number.
  • Mixed expressions with int promote to decimal. Mixing decimal and float is a compile error because no implicit precision policy is defined.
  • The current compiler subset supports decimal +, -, *, /, %, and numeric comparisons. Mixing with int keeps a decimal result.
  • Overflow / underflow / precision issues are treated as OverflowException.

3.3 enum and int

  • Aloe does not have a parenthesized cast syntax (e.g., (T)x).
  • Type conversions are performed via the as operator (see 15.1).
  • Implicit and explicit conversions between enum and int are prohibited.
  • Mixing enum and numeric types in an expression is a compile error (except bit ops on bitfield enum).
  • Internal representation of enum / bitfield enum is int32.

3.4 byte and char

  • byte:
    • Range is 0-255.
    • Arithmetic between bytes is allowed, but out-of-range may be an error.
    • Mixed expressions with int promote to int.
  • char:
    • Arithmetic on char is not allowed.
    • Comparisons (==, <, >, etc.) are only allowed between chars.
    • No implicit conversion to/from numeric types.

3.5 NaN / Infinity

  • Numeric overflow/underflow are handled as exceptions, not NaN/Infinity.
  • ZeroDivisionException is thrown for division or modulo by 0 / 0.0.
  • The modulo operator accepts int, float, and decimal operands. int/float pairs promote to float when either operand is float; decimal/int pairs promote to decimal.

4. Blocks & Scope

Blocks are delimited by { and }, and each block introduces a new scope.

  • main block
  • Class definition block
  • Method definition block
  • Any { ... } block

4.1 Static (lexical) scope and shadowing

class Sample {
    field value: int = 1;
    method foo(): void {
        var value = 2;        // shadows the field
        print(value);         // 2
        print(this.value);    // 1
    }
}
  • Aloe uses static (lexical) scoping.
  • Declaring the same name in an inner scope shadows the outer one.
  • If a field name conflicts with a local variable, the local wins; use this. to access the field.

4.2 with-blocks (member access shorthand)

Aloe provides with blocks to write repeated member accesses more concisely. 

with (user) {
    .name = "Alice";
    .age = .age + 1;
    print(.name);
}
  • Inside with (expr) { ... }:
    • .Member is shorthand for (expr).Member.
    • expr is evaluated exactly once at the start of the block and stored (not re-evaluated).
  • _ is not special. There is no implicit variable for the with-target.
  • Nested with blocks:
    • The innermost with is used for resolving ..
    • Outer objects remain accessible via their variable names.
  • Multiple with targets may be listed in the same block (similar to C# using style):
with (user), (profile) {
    .name = "Alice";  // resolved against user, then profile
}
  • Resolution order is left to right.
  • The member resolves to the first target where it is found.
  • If the same member exists in multiple targets and resolution becomes ambiguous, it is a compile error.

with is syntactic sugar: it can be desugared into explicit obj.member accesses before type-checking and codegen.

4.2.1 Type-based with (static / enumerator shorthand)

In addition to with (expr), Aloe supports with targeting a type name. 

with (TypeName) {
    .SomeStaticMethod();
    .SomeStaticField = 1;
}

Here TypeName must be one of:

  • a class type
  • a struct type
  • an enum / bitfield enum type

In this case, it is interpreted as a “type-context with”:

  • The content inside () is not evaluated as a runtime value.
    • The compiler resolves TypeName as a type; it does not instantiate anything.
  • Inside the block:
    • .Member is shorthand for TypeName.Member.
    • Accessing instance members inside a type-based with is a compile error.

Type-based with may be mixed with multi-target with; resolution is left-to-right and ambiguity is a compile error.

5. Variables & Constants

5.1 var (type inference)

var i = 10;
var f = 10.5;
var s = "Hello";
var c = 'A';
var b = 255;
var arr = [1, 2, 3];
var lst = (1, 2, 3);
var st  = {1, 2, 3};
var mp  = ["key": 10];
var fb  = new FizzBuzz();
  • The variable type is inferred from the right-hand expression.
  • var x = 1; is always int.
  • var x = 1.0; is treated as float.
  • var x = invalid; is a compile error (invalid is not assignable).
  • If the RHS expression is of type object, the inferred type is object.
function SomeFunc(): object {
    return 123;   // boxing to Integer
}




function main(args: string[]): int {
    var x = 1;            // int
    var a = 123;          // int
    var v = SomeFunc();   // object
    return 0;
}

5.2 let (explicit type)

let i: int = 10;
let f: float = 10.5;
let d: decimal = 10.12345678901234567890:d;
let s: string = "Hello, Aloe!";
let c: char = 'A';
let b: byte = 255;




let arr: int[] = [1, 2, 3];
let lst: int() = (1, 2, 3);
let st : int{} = {1, 2, 3};
let mp : map<string/int> = ["key": 10];
  • let x: Foo = invalid; is a compile error (invalid is not assignable).

5.2.1 Uninitialized references

Declarations of reference-typed variables may omit initialization. In that case, the reference is treated as invalid (uninitialized and invalid are not distinguished). 

var obj: Foo;        // OK (uninitialized reference)
obj.Value;           // runtime exception (InvalidReferenceException)
  • An uninitialized reference-typed variable is treated as invalid at runtime.
  • Member access on an invalid reference throws InvalidReferenceException.

5.2.2 Implicit unbox cast (non-consuming)

Operator/condition implicit-unboxing prototype (2026-10-14): arithmetic, ordering and primitive/reference comparisons extract matching boxes without consuming or changing aliases. Named box operands supply their own primitive kind; opaque references use the peer primitive/named-box kind or a fixed numeric expected result type. Two opaque numeric operands without that context are rejected; use explicit as casts. Integer-only masks/shifts/complement provide an int context for opaque references, while named Byte and other non-int kinds remain rejected there. Native byte/int/float/decimal arithmetic promotion applies after exact extraction; extraction performs no conversion or parsing, and decimal/float mixing remains rejected. if/while, not and/or provide a bool context. Expressions evaluate once from left to right; failed left extraction prevents right-side effects and short-circuiting skips the unselected right expression and cast. Two reference operands of ==/!=, including named boxes, retain ObjectId identity comparison; a primitive/reference pair extracts for scalar comparison. Comparisons with invalid remain validity checks. Invalid or incompatible boxes throw the existing implicit-as InvalidCastException and preserve the source reference. Existing array/class/function/GC roots and Tick/getter reads apply. String/char/bool operands support only their existing native comparisons/logical operations; no string concatenation or numeric parsing is added. No new syscall/opcode/codec layout; direct WASM boxes and dynamic runtime kind inference remain unsupported. See the operator-unboxing decision. This example returns 42 after AloeBC round-trip.
function main(args: string[]): int {
    var number = new Integer(40);
    let increment: object = 2;
    var enabled = new Boolean(true);
    var alias = number;
    if (enabled and number == alias and number != invalid) {
        var total = number + increment;
        if (total == 42 and number == 40) { return total; }
    }
    return 0;
}

In contexts where the expected type is fixed to a primitive type P, an implicit unbox cast is permitted for expression E. An implicit unbox cast does not consume the reference (it does not invalidate a variable).

Examples of contexts where implicit unbox casts are permitted:

  • let x:P = E; (initialization)
  • x = E; (assignment, where x has type P)
  • return E; (function return type is P)
  • f(E) (parameter type is P)

Implicit unbox casts are semantically equivalent to E as P, and throw InvalidCastException on failure. Using an alternate value via ifnot is available only with an explicit as (see 15.1).

Success conditions (no conversion is performed):

  • The runtime value of E is the primitive P.
  • Or the runtime value of E is the corresponding box object (e.g., Integer) and P can be extracted via ToXxx().

Prohibited:

  • No numeric type conversion (e.g., do not implicitly convert Integer to byte).
  • No parsing or format conversion (e.g., do not implicitly convert "123" to int).
let o: object = 123;      // boxing: Integer
let i: int = o;           // OK (implicit unbox cast) == (o as int)




let s2: string = o;       // failure (no conversion) throws InvalidCastException

5.3 Constants (const)

const MaxCount: int = 100;
const Pi: float = 3.14159;
const AppName: string = "Aloe VM";
  • const variables are not reassignable.
  • const requires a type annotation.

6. Fields

Fields in class/struct are declared with the field keyword.

class Sample {
    private field count: int = 0;
    readonly field id: int;




    construct(id: int) {
        this.id = id;
    }
}
  • field ... normal field.
  • readonly field ... assignable only inside the constructor; read-only afterward.
  • A class variable member cannot be public. A public field is a compile error.
  • A class member variable is private state owned by the Object itself and cannot be read or written directly by another Object.
  • State exposed outside the class is provided through a public property.
  • Structs are value types; the Object ownership / CallBuffer rules in this specification apply to class instances.

7. Class / Struct / Interface / Trait

7.1 class

class Player {
    private hp: int;




    construct(hp: int) {
        this.hp = hp;
    }




    public property HP: int {
        get {
            return hp;
        }    }




    public async method damage(amount: int): void {
        hp -= amount;
    }




    private method calculateDamage(value: int): int {
        return value * 2;
    }
}
  • Class is a reference type.
  • sealed class cannot be extended via extends.
  • Only single inheritance is supported.
  • Mutable State is owned by an Object, and only that Object may modify its member variables.
  • Another Object reads state through a public property and requests state changes through a public async method.

7.1.1 public property (instance)

  • A public property is a synchronous Query for reading the state of an Object instance from another Object.
  • An instance public property has no setter. External assignment such as player.HP = 100; is a compile error.
  • When invoked from another Object, the getter observes the target Object's Committed State.
  • When the Object itself reads a member variable, it observes the latest Volatile State for the current Tick, falling back to Committed State if no Volatile value exists.
  • Whether public property getters must be side-effect-free remains an open issue; restricting them to read-only Queries is the current candidate.

7.1.2 public static property

  • A public static property belongs to a type's static context, not to any Object instance.
  • In TypeName.Property, TypeName is resolved as a type / static namespace and is not evaluated as an Object Reference. Object ownership and Volatile / Committed rules therefore do not apply.
  • A public static property may define both a getter and a setter. Assignment TypeName.Property = value; invokes the setter synchronously.
  • A static property setter is not enqueued into the Static CallBuffer. Use a public static async method when an asynchronous command is required.
  • Inside a setter accessor, the assigned value is available through the implicit name value.
public static property score: int {
    get { return scoreValue; }
    set { scoreValue = value; }
}

Game.score = 100;
var score = Game.score;

7.1.3 public / private / protected instance methods

  • Every public instance method callable from another Object must be async.
  • A public async method must return void. Aloe does not introduce Task<T>, Future<T>, Promise<T>, await, or continuations for these calls.
  • In Aloe, async does not mean C#-style async/await; it means enqueueing a method invocation in the target Object's CallBuffer.
  • Private / protected instance methods execute synchronously and may return values.
  • At runtime, if targetObject == currentObject, the call is a self call and executes synchronously without entering the CallBuffer.

7.1.4 static methods

  • Ordinary static methods execute synchronously and may return values.
  • A public static async method may be defined and must return void.
  • A public static async method uses a Static CallBuffer owned by its class / type.
  • The C# reference VM processes each type's queue FIFO and serializes calls for that type; different types may run in parallel on the VMThread pool. Tick waits for calls enqueued during processing to reach quiescence.

7.1.5 constructor

  • The recommended model is: new executes the constructor synchronously, fully initializes the Object, then returns its Object Reference to the caller.
  • Constructors do not use CallBuffer.
  • Whether passing this to an external async call before constructor completion is prohibited remains an open issue; prohibition is the current candidate.

7.2 struct

Constructor exception flow (2026-10-20): each reachable catch starts from the fields definitely initialized before try.   • If P is a primitive in E as P:
    • If E is primitive P, it succeeds as-is.
    • If E is the corresponding box object (e.g., Integer), it succeeds by unboxing via ToXxx().
    • Otherwise it fails (InvalidCastException).
  • Omitting ifnot is equivalent to ifnot throw.
  • ifnot throw throws InvalidCastException.
  • as does not perform conversions (no numeric conversions, no parsing, etc.).

15.3 unbox operator (consuming unboxing)

unbox extracts a primitive value from a reference variable and invalidates the variable on success. This is a “consuming unboxing” (move-like unboxing). 

let o: object = 123;         // boxing: Integer
let i: int = unbox o;        // i = 123, o becomes invalid
  • The operand of unbox must be an assignable reference variable (an lvalue).
  • unbox x may only be used in contexts where the expected type is fixed to a primitive P.
  • Evaluation rules (x is evaluated exactly once):
    • If x is invalid: throw InvalidReferenceException (and x does not change).
    • If unboxing fails: throw InvalidCastException (and x does not change).
    • If unboxing succeeds: return the value, then invalidate x as if delete x; were executed.
  • Unlike implicit unbox casts, unbox consumes the reference variable on success.
Current direct WASM scalar prototype (2026-10-19): synchronous free functions support typed Int, Float, Bool, Byte, Char, and enum parameters, locals, and returns. Int maps to i64, Float to IEEE 754 binary32 (f32), and Bool/Byte/Char to i32; Char is zero-extended from one UTF-16 code unit. Numeric operations with at least one Float accept Float/Int/Byte operands; arithmetic follows VM binary32 promotion, and mixed comparisons widen to f64 to preserve VM int32-vs-float ordering. Float modulo uses binary32-preserving scaled subtraction and follows the dividend sign. It traps for a non-finite dividend, a NaN divisor, or a zero divisor; an infinite divisor follows VM behavior and returns the finite dividend. Other runtime guards trap non-finite results, multiplication/division underflow to zero from nonzero operands, division by zero, out-of-range numeric operands, and non-finite Float parameters. Decimal operations, numeric conversions, Syscalls, arrays, and object operations remain unsupported. Source and AloeBC checks preserve scalar distinctions across shared physical WASM types.
Current compiler int bitwise subset (2026-10-11): &, | and ^ accept two int operands; unary ~ accepts int; << and >> accept an int value and int shift count. Results are int. Operands are checked against signed int32 limits at execution, and shift counts must be 0..31. Left shifts discard higher bits; right shifts extend the sign bit. Invalid ranges raise VmException in the VM and trap in direct WASM. Byte, bool, char, float, decimal, normal enums and int/bitfield enum mixing are compile errors. Existing same-type bitfield enum operations retain enum identity. Comparisons bind more tightly than bitwise operators, so write (value & mask) == mask for bit tests.

16. Exceptions

Implemented synchronous subset: try { ... } catch { ... } catches any .NET exception raised while executing Aloe bytecode in the same synchronous call stack, including synchronous callees. A type-only clause such as catch (ZeroDivisionException) { ... } catches an exception assignable to one of the existing supported exception classes; multiple clauses in one try are tested in source order and the first assignable type handles the exception, with catch-all permitted only as the final clause; a nonmatching exception continues to an outer handler or escapes the VM. Supported names are Exception, SystemException, ZeroDivisionException, InvalidReferenceException, InvalidCastException, OverflowException, ArgumentException, IndexOutOfRangeException, and VmException. Catch clauses do not bind exception values. Bare throw; rethrows the active exception and is valid only inside a catch block. Exception construction or throw expressions, finally, exception handling inside async functions, and direct WASM are unsupported. The separate as T ifnot throw cast fallback remains supported. Async CallBuffer propagation and Tick failure rollback remain unresolved; the rest of this chapter is a design draft.

19. Object / Tick / CallBuffer Runtime Model

Each Aloe class Object owns its Mutable State. State-change requests from another Object are received through public async methods + CallBuffer. Internal changes during a Tick are held as Volatile State and become Committed State at the end of the Tick.

19.1 Object ownership and state visibility

  • Only an Object itself may modify its member variables.
  • Another Object reads state through public properties and requests changes through public async methods.
  • Another Object cannot directly read or write a class member variable.
  • A public property read from another Object observes Committed State.
  • An Object reading its own member variable observes the latest Volatile State for the current Tick, or Committed State if no Volatile value exists.

19.2 Volatile State and Tick Commit

  • Member-variable changes do not modify Committed State directly during a Tick; they update Volatile State.
  • Semantically the Object has a Volatile State, but an implementation may store only Dirty Member + Volatile Value using lazy copy.
  • At Tick end, Volatile → Committed is performed; afterward Volatile State is discarded or reset.
  • The previous field-change TaskChangeBuffer / Change Record model (SET / ADD / SUB, etc.) is removed.

19.3 Instance / Static CallBuffer

  • Each Object has an Instance CallBuffer. A public async method call from another Object is enqueued rather than executed immediately.
  • Appending to CallBuffer is mutually exclusive, and entries execute in recorded order.
  • The C# reference VM serializes calls for the same target Object and synchronizes Heap operations. Different Objects may run concurrently and their order is not deterministic; accesses through shared Object references require an ownership discipline that the prototype does not enforce.
  • A public static async method uses a Static CallBuffer owned by its class / type and is executed before the current Tick ends, including calls enqueued while draining.

19.4 self calls and synchronous calls

  • At runtime, if targetObject == currentObject, the call is a self call and executes synchronously.
  • Private / protected instance methods, ordinary functions, and ordinary static methods execute synchronously and may return values.
  • A Host-state synchronous static Query such as Keyboard.isDown may be provided; Host-side Thread Safety requirements remain an open issue.

19.5 async CallGraph

  • Public async instance methods and public static async methods participate in CallGraph analysis.
  • An async-to-async call adds an edge.
  • Self cycles, two-node cycles, and cycles of any larger size are compile errors.
  • For interface / virtual / override dynamic dispatch, all statically reachable call targets are included.
  • SCC or an equivalent algorithm may be used; validation may be repeated at final link time.

19.6 Tick Quiescence

Async Calls enqueued during Tick processing are also processed in the same Tick.

Running async method count == 0
AND
all Instance CallBuffers == empty
AND
all Static CallBuffers == empty
AND
Scheduler pending work == 0
  • The state above is Tick Quiescence.
  • Ordinary CallBuffer entries are not carried into the next Tick.
  • If a new Call is added during the Tick, Quiescence has not been reached.

19.7.1 Explicit GC control

  • GC.debug is a runtime-provided read/write public static property<bool>. GC.debug = true; enables GC diagnostic logging and false disables it. Its current value can also be read, for example var enabled = GC.debug;. It is independent of VM instruction tracing.
  • GC diagnostics may include per-work elapsedMs and memory metrics (heapUsedBytes / heapReservedBytes, plus managedBytes when available). They may also include separate phase timings for ReferenceGraph / Plan / Sweep / Move / FreeBlock and a total. When GC debug was enabled at least once during the run, the Runtime may emit a [PERF] Program end summary containing program execution time and cumulative GC time.
  • A REPL may route GC diagnostic output to the current session output, so GC phase logs can be inspected interactively after GC.debug = true; followed by GC.require() / GC.finish().
  • GC.require() refreshes Runtime Temporary References at a safe point and advances one normal budgeted GC Plan / Sweep / Move / FreeBlock unit.
  • GC.finish() synchronously advances GC until the currently requested unfinished GC cycle completes. If there is no active GC Plan, it returns without doing work and does not create a new Plan. Reclaimability is determined by the same rules as GC.require().
  • The VM may request automatic GC at safe execution points; normal programs are not required to call the explicit API for memory reclamation.
  • tick() is responsible for committing reference state, not for GC Plan / Sweep / Move / FreeBlock.

VM Tick is separate from a Game Render Frame, VSYNC, Renderer, or GPU.

19.8 Object Reference members

  • A class member may hold an Object Reference.
  • Reference members follow the same Committed / Volatile rules.
  • If Committed Reference and Volatile Reference differ, both referenced Objects remain alive until Tick end.
  • After Commit, the Volatile Reference becomes the new Committed Reference and the old Committed Reference is released.

19.9 Reference Counting and Reference Groups

  • Reference Counting is the basic lifetime mechanism for Object References.
  • An SCC in the Object Reference Graph is a Reference Group and receives a unique Group Handle.
  • References between Objects inside the same Group do not count as External References keeping the Group alive.
  • References entering a Group member from outside the Group are Group External References; a Group with External Reference Count 0 becomes a destruction candidate.
  • New edges may merge Groups and removed edges may split Groups; graph maintenance is normally concentrated at Tick boundaries.
  • An Object / Group whose reference-typed members changed may be marked Reference Dirty and prioritized for local re-analysis.

19.10 Destruction Candidates and Runtime Temporary References

  • An Object / Reference Group whose Reference Count reaches 0 is not freed immediately; it is marked as a Destruction Candidate and destroyed after safety checks during Tick-end processing.
  • A CallBuffer target Object and Object Reference arguments are Strong References until the Call completes.
  • Object References on the VM stack, running method arguments, CallBuffer entries, and Volatile References are Runtime Temporary References considered by lifetime calculation.
  • Weak References are not part of the initial specification.

19.11 async return model

An async call is a pure fire-and-forget Command. Aloe does not introduce Future, Promise, Task<T>, await, or async return values. Values are obtained from Objects through synchronous Queries such as public properties.

19.12 Open issues

  1. Whether public property getters are restricted to side-effect-free read-only Queries.
  2. How broadly mutable global variables / mutable static fields and the backing state of settable public static properties are allowed, and how VMThread synchronization for that state is defined.
  3. Thread Safety requirements for Host synchronous Queries.
  4. Final constructor execution rules and whether this may escape through an external async call before construction completes.
  5. Whether an unhandled exception in an async method causes Tick Failure, discards Volatile State, and is rethrown from tick() to main.
  6. Handling of unprocessed CallBuffer entries and irreversible Host side effects on Tick Failure.
  7. Executor and serialization rules for Static CallBuffer.
  8. Complete determinism for Replay / Lockstep using Sender Object ID / Sender Sequence / Logical Call Order or similar.
  9. One-Tick latency caused by same-Tick property visibility and whether Phase semantics are needed.
  10. Object Reference properties and Object References stored indirectly through Collection / Array / Map / struct as Reference Graph edges.
  11. Reference Group merge / split / Dirty local SCC algorithms.
  12. Visibility and lifetime of Objects created or destroyed during a Tick.
  13. Whether Host side effects such as Audio / Network / File / Renderer commands are delayed until after Tick Commit.
