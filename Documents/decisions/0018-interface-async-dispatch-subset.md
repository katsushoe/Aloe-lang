# Interface Async Dispatch Subset

Status: Accepted and implemented, 2026-10-14; interface casts, boolean type tests, stable-local parentheses/and/or/not if/else-if/else/while condition narrowing, collection references and interface inheritance added 2026-10-14; declaration-preserving direct body writes and nested conditional state merging and single-pass with flow and synchronous exception-flow joins and scope/storage-aware while/foreach entry invalidation and unique common-interface ancestor joins across mixed boolean proof groups added 2026-10-15; exit-guard continuation facts, both-continuing branch common-interface joins, literal-true while break-edge joins, and try/catch common-interface joins plus sole-continuation path restoration added 2026-10-16; nested terminal loop/try-catch write-scan precision, dead loop-transfer tokens after direct throw/return and non-loop-exit conditional chains, common-interface joins across reachable break edges, constant-condition exception-edge filtering with unreachable try-write exclusion, and finite loop-head type-state fixed points added 2026-10-18; typed single-clause catch syntax is recognized by the loop-flow scans and preserves the same conservative catch-edge handling, added 2026-10-19.

## Context

The language design includes interfaces, but the compiler and VM do not have a separate interface table or dispatch opcode. Public instance operations in the implemented subset are `public async` methods that enqueue work for a later `tick()`. A first interface slice should use this existing call contract and dispatch path while making its limits explicit.

## Decision

An interface may declare unique method signatures with `void` return types. Parameters use existing compiler-supported types. Interface declarations must precede implementing classes. A class lists one or more previously declared interfaces after `implements`; duplicate names are errors. Each contract must resolve to a matching public async instance method, including an inherited method. A class derived from an implementing class is assignable to the interface.

An interface may list one or more parents after `extends`. Parents must be previously declared interfaces; self/forward references and duplicate direct parents are errors. This ordering prevents cycles. Parent contracts are flattened into the child. Diamond inheritance and independently declared same-name contracts coalesce when their parameter and return types match exactly; parameter names are ignored. Conflicting signatures and local redeclaration of inherited names are rejected. Classes implementing the child must satisfy every inherited contract. Child-interface references upcast to their parents, and class/interface assignability, runtime casts/tests and async dispatch include transitive conformance. Invariant collection identity is retained; child-interface collections cannot be implicitly aliased as parent-interface collections.

Variables and parameters may use an interface type. A class instance assignable to that interface may be assigned or passed there. Calling a contract method enqueues the matching implementation through the existing `InstanceVirtualAsyncEnqueue` syscall. The dispatch table includes known classes assignable to the interface, and async call-graph reachability includes their selected implementations. Runtime object identity and storage remain unchanged.

Checked `as I` casts and boolean `value is I` tests accept interface targets. At compile time the target descriptor is the closed list of known classes assignable to the interface, including classes inheriting conformance. An interface with no known implementer uses its own reserved interface name as a class descriptor, which cannot collide with a class declaration and therefore always fails the runtime check. The existing `ObjectCast` / `ObjectTryCast` syscalls perform the checks; no interface object, runtime interface table, syscall or AloeBC change is added. Positive local-reference `is` tests in an if/while condition may be parenthesized and joined by `and`; their facts narrow locals inside the controlled body until direct writes. An `or` retains facts guaranteed by every branch for the same local by intersecting declared ancestor sets and selecting a unique most-specific common interface. This preserves identical/related joins and adds sibling and diamond joins. Flat and nested OR/false-AND alternatives intersect ancestor sets before outer selection. Parentheses and negation retain sets; an ambiguous inner pair can become unique with an outer alternative, independently of alternative grouping/order. Only a unique final interface narrows the body; no synthetic intersection is exposed. No common ancestor, multiple incomparable most-specific candidates or a branch without a fact removes the fact. Simultaneous true-AND/false-OR proof groups now union guaranteed ancestor sets per local from every operand, independently of their direct candidate-selection ambiguity. Atomic tests export their own guaranteed ancestors even if a direct conjunction cannot choose one type. Outer alternatives intersect those sets before unique-interface selection, supporting mixed AND/OR/negation groups. Direct conjunction narrowing still uses the existing related-type rule; no anonymous intersection or arbitrary incomparable type is exposed. Missing facts and different local names still remove an alternative candidate. Common method signatures do not establish ancestry, and unrelated conjunction intersections are still not synthesized. Negation flips the selected truth branch. Alternative joins omit constant operands that cannot produce the selected truth value (false operands for true OR, true operands for false AND); unknown alternatives still participate. Logical-expression parsing suppresses local write tracking and restores incoming metadata for statically short-circuited right operands, without removing type checks or emitted code. If/while proof filtering uses parser-observed reachable condition-write slots rather than lexical unbox occurrences; enclosing try write scopes receive reachable consumers only. The constant evaluator can also return short-circuited operand ranges; loop-entry scans use them for outer/nested if/while conditions and assignment/initializer right-hand sides, including grouped call arguments and array elements. Top-level commas divide independent argument/element evaluations; other expression shapes remain conservative. Constant-false while bodies contribute no back edge, so their false exit uses the evaluated condition state. Entry scans preserve reachable condition consumers before skipping constant-false nested if/while bodies. True AND and false OR conditions require facts from every operand; true OR and false AND conditions retain only facts common to the alternative paths. Only guaranteed positive interface tests produce a usable interface type; negative tests do not infer exclusion-based types. Double negation and De Morgan forms reuse this analysis. Multiple related interface targets in an and conjunction choose the most specific interface; unrelated intersections are not formed. Already conforming static class/interface types retain their original members. Original local declarations are retained in a separate compiler-only per-slot registry, cleared between functions and populated for named/implicit locals. Direct body assignments validate against that declaration rather than the temporary narrowed type; assignment then restores declared metadata and discards temporary facts, even for self-assignment or a conforming RHS. Local delete and consuming-unbox clear paths discard facts as well. Earlier reads may use the fact; later reads need a fresh is test or cast unless the declaration already supplies the member. Runtime consuming-unbox still clears a reference only on successful extraction. Nested if/else-if branches now capture incoming local metadata by slot, restore it before compiling a sibling branch, and merge only fallthrough outcomes. A temporary condition proof is removed without restoring over a write. Joins preserve an incoming fact only if every fallthrough branch retains it or a more specific assignable type; returning branches do not kill facts on the surviving path. When both explicit if/else branches continue, their final per-local states join through a unique most-specific common nominal interface. Same-type, child/parent and sibling common ancestors are supported, including nested if/else and else-if joins. Missing or invalidated facts, unrelated types and ambiguous common ancestors add no proof. Existing more-specific incoming facts remain intact. An explicit if/else with exactly one continuing branch exports its final interface state before temporary condition proofs are restored. Else-if chains use the same rule. Writes and consuming operations remain invalidated; fresh guards can establish new facts. A no-else if whose then path cannot fall through additionally applies guaranteed positive false-condition facts to its continuation: for example, if (not (value is I)) { return; } allows subsequent I calls. Return/break/continue/bare-rethrow reachability uses the existing conservative statement analysis, without exclusion types or new runtime branches. Assignment/delete/consuming unbox discard these facts under the original declaration contract. While false-condition exits apply positive facts guaranteed at each re-evaluation, including after continue, and merge them with reachable break snapshots. Possible-write entry invalidation remains in force. When the body is proven not to reach the next condition evaluation (currently straight-line statements, supported with/if/try-catch paths, and nested while/foreach statements followed by an outer terminal, without a reachable continue targeting the outer loop), first-iteration condition facts remain available in the body and the zero-iteration false exit joins reachable break snapshots. A nested constant-true while with no reachable break targeting itself is non-fallthrough. Nested while true-body and false-exit analysis also applies the existing positive condition proofs, joining the zero-iteration false exit and reachable breaks with nested back edges; the proofs are discarded on writes and consuming operations. Transfer lookahead distinguishes break/continue targets and ignores unselected/dead paths; inner-loop breaks do not make the containing while escapable. A reachable continue or a body path that falls through to the next condition evaluation remains conservative. Literal-true while exits use reachable breaks only. Loop-entry scans track try ranges whose catches can rejoin the loop. Inside those ranges, writes on returning/rethrowing branches and nested terminal try/catch blocks remain potential loop-carried effects. Outside exception-rejoining ranges, conditional paths proven to return, rethrow or never fall through can be excluded from the surviving loop state. For a while entry, a terminal conditional path with no reachable continue may also exclude writes reaching only that while break exit, because actual break snapshots remain in the exit join. Nested-loop targets and foreach exit restoration are excluded from this optimization. Arbitrary control-flow graph transfer beyond the finite nominal loop-head domain, broader foreach exit transfer, edge-specific exception-mutation analysis, intersection types and ambiguous ancestor-set propagation remain deferred. Same-named shadow locals use distinct slots. A consuming unbox in a condition suppresses proofs for that local. Single-pass with blocks now share surrounding local flow state, so earlier reads use incoming facts and assignment/delete/consuming unbox invalidate the original slot through body exit. Nested conditionals retain sibling isolation and fallthrough joins, and shadow slots remain independent. Existing class/named-box target expressions still evaluate once, left to right; their captured references remain usable after the original variable changes or is invalidated. Consumption in a target expression invalidates its local before the body. Interface-typed with targets remain unsupported; an explicit checked class cast supplies a supported target. Synchronous try/catch snapshots incoming slot metadata and tracks assignment/delete/consuming-unbox slots in every active try scope when the compiler considers their path reachable, including nested handlers and writes on returning/rethrowing paths. Compile-time unselected if/else-if arms and statements after terminal exits are excluded. Catch restores incoming facts but discards those for any slot possibly written on a compiler-reachable try path, without carrying new try-local proofs. The normal and catch exits merge only fallthrough outcomes; returning/rethrowing outcomes do not invalidate surviving continuation facts. If only one outcome falls through, its interface-flow snapshot continues; if both fall through, the compiler joins facts guaranteed by both. Same-named shadow locals remain distinct slots. Failed extraction retains runtime references, while static recovery requires a new test or cast. No runtime exception or bytecode contract changes. While/foreach now scan their complete header/body before compiling the header, discarding incoming facts for possibly assigned/deleted/consuming-unboxed local names. Nested loops/handlers and unreachable writes are conservatively included. Lexical block scopes distinguish let/var locals and foreach item/key/value bindings from incoming variables. Declaration names become shadows only after the initializer and semicolon; foreach bindings become shadows only at their body. Initializer and source-expression consumption therefore still invalidates outer slots, and writes after a shadow scope ends resolve to the outer slot. Mutation scans also distinguish local bindings from heap slots: a dot-qualified field assignment does not mutate a same-named local; delete/unbox of a field or indexed element does not consume its receiver binding. A shared lexical helper recognizes plain parenthesized local targets while excluding field/index/call or parenthesized cast receiver paths. Nested operations in indexes/call arguments are independently scanned, so their actual local consumption still invalidates facts. Condition unbox guards use the same target distinction. Existing reference-target validation, getter/with access and readonly-property rules are unchanged. This is compile-time scanning only; it changes no lexical binding or runtime rule. Earlier reads outside the loop remain narrowed. Each while condition may re-establish guaranteed proofs for its iteration body; nested conditionals/with/try writes use ordinary invalidation and joins. Foreach requires a fresh test or cast for a mutated opaque local. Array/List/Map-key/Map-pair/pipe foreach all pass through one loop-state wrapper. Loop exits join the reachable condition-false, break and (for foreach) exhaustion states, preserving untouched peers and discarding facts not guaranteed by every exit. A literal-true while joins facts captured at reachable break edges, including multiple exits. Foreach exhaustion/zero-iteration paths and general fixed points remain conservative; while false-condition exits may export their guaranteed facts, including after continue re-evaluates the condition. While condition tests re-establish body facts for each iteration; writes cannot leave stale facts at a backedge. An explicit else block receives false-condition facts independently of then-branch writes. Outer false-branch facts propagate into else-if conditions and their branches, with separate state restoration and fallthrough merging at each join. Balanced groups identify complete chains. Arbitrary loop fixed-point/continue and exception-edge analysis beyond the implemented finite nominal type-state, plus ambiguous/no-common-ancestor joins and interface intersections remain deferred. While condition facts apply to each iteration after entry invalidation; exits join reachable break states with applicable false-condition facts.

Interface references are supported as array, List and Set elements and Map keys/values. Existing assignment checks allow conforming classes; element reads and foreach preserve the static interface type. Collection types remain invariant. Their class-name descriptor starts with the declared interface name and then the sorted known implementing class names. The reserved interface name cannot be an allocated class type, but retains nominal collection identity: different interfaces with identical implementers still have distinct descriptors. Empty collections also work when an interface has no known implementer. Existing VM class-reference collection checks, ObjectId identity, strong edges, Tick snapshots and cast shape checks apply without an opcode, syscall or AloeBC change.

This subset does not support default methods, properties, fields, flow-dependent type narrowing beyond the bounded subset described below, or direct WASM. Interface values are references to implementing class instances; no interface wrapper object or AloeBC format change is introduced.

While and foreach entry analysis excludes conditional writes whose only loop rejoin is a break from the current loop, outside exception handlers that can return to a back edge. Breaks targeting nested loops do not qualify. Foreach captures break states in a scoped frame keyed to loop depth, so array/List/Set, Map-key/Map-pair and pipe iteration join only their own reachable breaks with the conservative exhaustion/zero-iteration state. Break-only mutations therefore preserve repeated entry reads but invalidate exit facts. Common-interface joins discard an existing fact contradicted by any incoming exit before selecting a shared ancestor.

Excluding terminal branch bodies still records reachable consumers in the evaluated condition; statically short-circuited operands remain excluded. Foreach also applies the no-back-edge proof to preserve first-iteration facts. In that case the exhaustion exit uses the source-evaluation snapshot (the zero-iteration path), joined with entered break states; source consumption is not restored away. Returning/nonfallthrough bodies therefore do not invalidate a surviving zero-iteration fact merely because they write before leaving.

A limited nominal invariant preserves an incoming interface fact across self-assignment, parenthesized forms, complete class construction and outer-local/global-function results whose declared nominal type conforms to that interface, including final checked casts to a conforming nominal target. Only entry/normal-exhaustion analysis uses the invariant; ordinary parsing still forgets facts immediately after writes. Incompatible/unknown assignments and reachable consumers invalidate it. Arbitrary assignment expressions and general fixed points remain deferred. Statement-end lookahead resumes at the token after a balanced group, including an immediately following semicolon, instead of accidentally scanning into the next statement.

Sequential statements and if/else-if/else branches additionally track each incoming interface candidate through local assignments, excluding nested loops and handlers. Every reachable fallthrough/continue back edge must conform; return/throw/break paths contribute no back edge, and joins intersect only continuing branch states. Conforming nominal assignments before every back edge can re-establish the entry invariant after incompatible/unknown intermediate assignments. A self-assignment preserves the current abstract state, so it cannot repair a lost fact. Reachable consumers clear the current path state; later nominal assignments can re-establish it before the back edge. Condition-consumed slots cannot be re-established by proofs collected from that same condition. Ordinary parsing still rejects unguarded intermediate reads, and continues before restoration remain invalidating. Loop-head transfer now iterates a finite abstract type state to a fixed point, joining the first body entry with reachable fallthrough/continue back edges through a unique most-specific common interface. Nested while conditions are reapplied on each evaluation and break snapshots remain exits. If the finite iteration bound is exceeded, the state widens to unknown. This is not a general control-flow graph, arbitrary edge-specific exception analysis, or intersection-type inference.

Interface guards additionally re-establish true/false branch candidates when their guaranteed interface conforms to the incoming candidate. Existing boolean proof collection handles negation and alternative joins. Shadowed names, incomplete alternatives, weaker parent-only proofs and reachable condition consumers remain conservative; no fact is invented for an initially unproven local.

Bounded loop transfer also supports with blocks and nested with scopes. It evaluates header target consumers before analyzing the body; each top-level target receives independent short-circuit analysis. The body uses a copied lexical shadow scope and shares enclosing-loop back edges, so continue/break/return preserve their targets without leaking declarations. Restoring assignments can re-establish candidates before a back edge, while the ordinary parser still owns captured receiver identity, intermediate-read checks and break-exit snapshots. Nested while/foreach statements isolate their own break/continue edges and join zero-iteration or source-consumption exits, inner back edges and reachable breaks. A candidate survives only when all relevant paths preserve it, including after nominal restoration. A nested while proven not to reach its own exit contributes no outer back edge. Synchronous catch-all try/catch analyzes normal flow from the incoming state and catch flow from cleared candidate facts; each reachable continuing path must restore the candidate. Typed catches, finally, and async exception edges remain outside this model.

## Alternatives

- Add dedicated interface metadata and VM dispatch: deferred because the existing virtual async dispatch syscall and closed class-name descriptor provide the required behavior without a bytecode-format change.
- Permit synchronous or value-returning interface methods: deferred because these do not match the current externally callable instance-method contract.
- Infer conformance structurally without `implements`: rejected because explicit conformance makes dispatch reachability and validation deterministic.
- Full control-flow graph analysis: deferred; per-slot metadata snapshots and fallthrough joins extend nested conditional writes while loop-entry mutation invalidation protects repeated regions and per-try mutation sets conservatively join exception paths without changing mutable-local assignment contracts.

## Security and operations

Dispatch candidates are limited to statically known classes that conform to the declared interface (directly or through a base class). The compiler emits only validated method indices; the runtime continues to apply its existing live-reference and async queue checks. No new external input, permission, persistence, or deployment behavior is added.

The existing per-object FIFO contract also applies to calls emitted across loop iterations. Selecting a runnable instance call scans the original queue once, removes only that selected entry and preserves the relative order of remaining entries, including calls skipped because their target is busy. A two-target regression checks FIFO without imposing an order across different objects. Interface-flow tests compare independent-target output as a multiset and retain per-target order checks where relevant. No runtime ABI or exception contract changes.
