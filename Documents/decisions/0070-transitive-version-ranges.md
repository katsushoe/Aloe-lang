# 0070 Transitive version ranges and deterministic backtracking

Status: Accepted (option A)
Date: 2026-11-23 JST
Adopted: 2026-11-23 JST, user response「A」
Implementation status: Not implemented. Product acceptance requires `.local/package-ranges-<date>/acceptance.json`.
Rubric: P07 (Transitive range reconciliation/backtracking contract). Extends 0031 (exact closure), 0038 (root range selection), 0046 (lock file).

## 問題

決定0031は依存関係の `versionRange` を完全一致の版だけに限り、決定0038はルートだけを `>=M.m.p <N.n.p` で選び、選んだ版で失敗しても後戻りしません。パッケージ仕様の例（`">=0.1.0"`、`"0.2.x"`）の書き方は「ビルドツール仕様で定める」とされたまま未定義でした。

## 決定

1. 範囲の書き方（ルートの指定とメタデータの `versionRange` で共通）
   - 完全一致: `1.2.3`
   - 下限のみ: `>=1.2.3`
   - 区間: `>=1.2.3 <2.0.0`（0038と同じ。下限を含み上限を含まない。区切りは半角空白1つ）
   - ワイルドカード: `1.x`（= `>=1.0.0 <2.0.0`）、`1.2.x`（= `>=1.2.0 <1.3.0`）
   - 各部分は0031の規則（ASCIIの10進数字、先頭の0なし）。`^`、`~`、プレリリース・ビルド接尾辞、複数範囲の組み合わせは扱いません（構文エラー）。
2. 同じ名前のパッケージは、依存関係全体で1つの版だけを選びます。
3. 選択と後戻り探索
   - 各パッケージについて、すべての要求を満たす版のうち最も新しい版から順に試します。
   - 選んだ版の依存関係が他の要求と矛盾した場合は、直前の選択を1つ古い版に変えて試し直します（深さ優先の後戻り探索）。
   - 試す順序は、パッケージ名の序数順と版の新しい順で固定し、同じ入力からは必ず同じ結果になります。
   - 試行回数の上限は既定10,000回とし、超えた場合は「探索上限に達した」エラーにします（上限はコマンドの引数で変更可能）。
   - 循環依存はエラーです（0031と同じ）。
4. ロックファイル（0046）
   - 有効なロックファイルがある場合は、そこに記録された版を優先します。各版がすべての範囲を満たし、ファイルのハッシュが一致することを検証します。
   - 満たさない場合や不一致の場合はエラーにし、黙って再解決しません。再解決は明示的な更新コマンドで行います。
5. 解決できない場合は、矛盾した要求の連鎖を表示します（例: `app 1.0.0 → A 1.4.0 requires C >=2.0.0` と `app 1.0.0 → B 0.3.0 requires C <2.0.0`）。
6. 既存の動作の維持: 0031の完全一致の解決結果（formatVersion1）、0038のルート範囲選択の出力（formatVersion2）の意味と順序は変えません。推移的な範囲解決の結果は新しい形式（formatVersion3）とし、各パッケージの選んだ版、満たした要求、索引のハッシュを含めます。時刻は含めません。
7. 本決定は、ローカルの索引（package-db.json）に対する読み取り専用の解決だけを扱います。取得・導入・信頼はP08〜P10で決めます。

## 受入テスト（実装時）

各範囲の書き方と構文エラー、ワイルドカードの区間への読み替え、1パッケージ1版、最新版の選択、後戻りで解ける組み合わせ、解けない組み合わせの矛盾の連鎖の表示、探索上限、循環依存、決定性（同じ入力で同じ結果）、ロックファイルの優先・不一致のエラー、既存のformatVersion1 / 2の出力の維持。両TFM全テスト、Release、英日のパッケージ仕様とビルドツール仕様の範囲の書き方の追記。
