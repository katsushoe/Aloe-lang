# Basic array prototype

Status: Accepted for the C# VM/compiler prototype, 2026-10-13.

## Context

Language chapter 10 defines array literals and `T[]` types. The VM already owns stable heap handles, field storage, Tick state and GC roots. Indirect references through collection elements remain unresolved in the VM specification; the array subset started with reference-free leaf values: int, bool, byte, char, float, decimal, string, normal/bitfield enums and existing immutable structs.

## Decision

Represent fixed-length primitive, string, enum and struct arrays as Aloe heap objects with reserved source-inexpressible type names `int[]`, `bool[]`, `byte[]`, `char[]`, `float[]` `decimal[]` and `string[]`, plus `enum:<Name>[]` for enum arrays and `struct:<Name>[]` for struct arrays. Each field is one element. Assignment, parameters, returns, class fields and queued arguments share the handle. Array literals evaluate elements once from left to right. Typed declarations and assignments give empty literals their element type; context-free empty literals are rejected.

Expose index/`Length` reads on array-valued functions, properties, literals, local variables and parenthesized expressions; element assignment accepts an indexed array expression. Iterate a captured handle in index order with `foreach`. The length stays fixed and each element is read when its iteration begins. Reassigning the source local does not change an active iterator. Writes use the existing Volatile/Committed Tick behavior; getter queries read committed array elements. Concurrent element operations use the existing heap synchronization, with no added atomic read/modify/write promise.

Array writes are forbidden during property queries. The compiler rejects direct getter assignments; the runtime also rejects writes through called functions, preserving the committed query boundary.

Built-in Syscall IDs 21..24 create, read, write and query length. They use the existing Syscall opcode and AloeBC representation. Runtime guards reject non-array handles, invalid integer indexes, incompatible elements and int values outside signed int32. No host capability is needed for these internal operations.

## Alternatives

- Managed CLR array values outside the Aloe heap would require separate root/GC/reference semantics, so they are not used.
- New array VM opcodes would expand bytecode encoding and validation before broader collection requirements are established; internal Syscalls reuse the existing path.
- Class/object array representation and guard rules are defined by the reference extension below. Nested arrays use ordinary counted strong heap-field edges, preserving the existing reference graph model; no separate collection ownership semantics are introduced.

## Impact and conditions

No installation, network or filesystem behavior is added. Arrays cannot be struct fields because arrays are references. Main's existing syntax-only `args: string[]` remains unchanged. Direct WASM, resizing and other collection types are outside this prototype.

Compiler, runtime and malformed-Syscall tests cover types, indexes, copies versus shared references, evaluation order, loops, class/Tick/GC boundaries and AloeBC round-trip. Japanese/English language and VM Syscall documents describe the same supported subset and errors. Progress tracks this as partial language coverage, not complete collection conformance.

Getter contents are committed queries; indexing a reference returned by a getter runs in the caller and reads current elements. Returned arrays are not snapshots. Receiver expressions evaluate once and remain stack roots while the index expression is evaluated.

Array foreach accepts the same primitive array expressions as read access, evaluates the source once and retains it through GC. Existing pipe foreach remains local-only. Constructor definite initialization treats the loop as possibly empty, even for a nonempty literal.

Primitive extension: byte[] integer literal adaptation applies to typed declarations/assignments and element writes; computed int values and other numeric kinds do not implicitly convert. Float create/get/set reject non-finite binary32 values; remaining element kinds match their existing AloeValue representations.

Array element writes evaluate target, index and assigned value once in source order. Bounds/kind checks occur at ArraySet after evaluating the value. Function/property/literal/parenthesized, this-field and with-property references use the same existing setter; general scalar lvalues and Length writes remain rejected. Getter-returned references are caller writes, while actual property queries retain their write prohibition.

Enum extension: source array types retain the nominal enum name across inference, declarations, assignment, index reads/writes, foreach, parameters and returns. Normal and bitfield enums share existing signed-int32 storage; reserved enum:<Name>[] descriptors distinguish heap array kinds without adding enum tags, declaration metadata, opcodes or codec changes. The runtime checks descriptor shape and int32 values, but cannot establish nominal identity for arbitrary untyped bytecode. This matches the existing enum representation; tagged enum runtime values would change every enum boundary and are deferred. Empty literals still need declaration/assignment contexts. Bytecode/runtime inputs need no compiler declaration table, and nonmember int32 values remain valid runtime enum payloads.

Struct extension: retain existing immutable AloeStructValue snapshots with nominal source/snapshot type names in reserved struct:<Name>[] heap entries. Source literals, index/foreach values and function/class/async boundaries preserve nominal types; runtime create/get/set require matching Struct snapshot names. Existing constructors reject reference fields, so nested structs require no new indirect reference-graph rules. Immutable payload sharing implements value-copy semantics without eager deep cloning; local/foreach field changes rebuild a separate snapshot, while whole-element assignment updates array aliases and preserves earlier copies. Indexed results allow field/read-only method/getter member chains. Direct element-field write-back captures the array/index and original immutable snapshot, applies the existing local struct field-path rebuild and replaces the whole element. ArrayGet checks bounds before the RHS; the captured snapshot is rebuilt even if the RHS replaces the same element. Earlier copies stay independent and aliases observe the replacement. Property/method-result assignment paths are rejected; getter-query writes remain forbidden. No atomic read/modify/write guarantee is added. Runtime field-layout validation remains the existing struct construction contract rather than a new declaration table. This keeps existing Struct opcodes and Syscall/AloeBC storage unchanged. Tests/documentation cover snapshot isolation, nominal types, nested/enum fields, constructors, GC, Tick and malformed operands.

Struct array field-write lowering uses implicit VM locals to retain the receiver/index/snapshot, existing StructGet/StructSet to rebuild nested fields, then the existing ArraySet. Targets evaluate once in source order; locals remain GC roots across RHS calls. Runtime/Syscall/codec formats are unchanged. Tests include nested/byte/enum assignments, two host-triggered GC cycles, Tick committed/current views, effectful RHS snapshot behavior, invalid readonly/type paths, getter mutation and pre-RHS bounds failure.

Nested extension: represent jagged arrays by appending [] to their inner runtime descriptor, preserving the base primitive/enum/struct descriptor. Every nested element is a live, non-null array handle with exactly one fewer dimension and the same base type. Source type/context/inference, chained reads/writes, foreach and function/class/async boundaries preserve the remaining rank/type. Existing Heap.SetField/SetVolatileField count strong references per element, including duplicates; replacement removes old edges, while Tick retains both Committed and Volatile child edges until commit. Existing GC follows these edges from outer roots. Exact decreasing rank prevents cycles consisting solely of ranked array edges; generic object leaf elements may form cycles and use existing SCC/reference-group semantics. Deep-cloned rows would break established shared array-reference semantics, so assignments share handles. Reference-free struct leaf snapshots remain unchanged. Test direct reference counts and child collection after replacement, sole outer roots, rank/type guards, nested empty/byte contexts, leaf structs/enums, chained field write-back and Tick/query rules. No new opcode/Syscall/codec format or GC implementation is added. General reference-element arrays follow the reference extension below.

String extension: store existing immutable managed AloeValue.String payloads in string[] heap fields, including nested string-array handles. Leaf String values have no Aloe ObjectIds and therefore need no outgoing object-reference edges; CLR-managed storage preserves their lifetime while fields/values exist. This preserves existing string/codec representation rather than introducing a separate string heap model. Create/get/set requires String kind and rejects Null/char/other kinds; source boundaries reject implicit conversions. Array aliases share element replacement, while previously read string values retain their contents. Nested arrays retain existing counted strong Object edges. Main args stays syntax-only without argument delivery; broader string APIs remain deferred; class/object arrays follow the reference extension below. Test empty/Unicode/escape literals, nested contexts/GC, function/class/async/Tick/query boundaries, incorrect element kinds and malformed reads/writes.

Reference extension: accept non-null live Aloe heap Object handles in class/object array fields, with ordinary counted strong edges, duplicate references and existing SCC cycle handling. Source class arrays are invariant but allow declared-class/subclass elements; first-element static type supplies inference. Compiler descriptors are class:<Base>|<AssignableClass>[], base first and remaining names ordinal-sorted from the completed module class graph. VM validates unique identifier names and exact runtime TypeName membership; it cannot independently verify inheritance/authenticity for raw caller-supplied descriptors. Nested descriptors match exactly. Adding a global runtime class table/AloeBC format migration is deferred because existing descriptors and virtual dispatch already use compiler-supplied constants; exact-only class storage would incorrectly reject dynamically derived values held in base locals; covariant mutable arrays would allow unsafe replacement. Object[] stores heap handles only, with no boxing or implicit downcasts. Indexed class elements expose public getters; async/virtual calls use existing local/with receivers. Readonly properties/private fields remain nonassignable. Source Object equality and newly constructed Tick object committed initialization are unchanged. Unrooted parent/child group reclamation can require successive existing GC passes. Tests cover inheritance/virtual dispatch, mixed object handles, nested getter chains, aliases/GC/queued references/committed queries, malformed allowlists/live kinds, duplicate edges and cycles; user docs describe all limits. No new heap/GC implementation, Syscall IDs, opcode or codec format is introduced.
