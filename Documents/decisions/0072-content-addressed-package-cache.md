# 0072 Verified acquisition into a content-addressed package cache

Status: Accepted (option A)
Date: 2026-11-23 JST
Adopted: 2026-11-23 JST, user response「A」
Implementation status: Not implemented (after 0071). Product acceptance requires `.local/package-cache-<date>/acceptance.json`.
Rubric: P09 (Verified acquisition and content cache).

## 問題

決定0071でフォルダーのリポジトリと、索引によるSHA-256・メタデータの照合を決めましたが、取得の手順、手元での保管（キャッシュ）、途中失敗・同時実行・オフラインの扱いは未定義でした。

## 決定

1. キャッシュはPC（インストールルート）全体で1つです。保管場所は `<インストールルート>\data\package-cache\sha256\<sha256>.aloepkg` です（インストールルートは既存の `ALOE_INSTALL_ROOT`、既定 `E:\Aloe`）。ファイル名は中身のSHA-256（小文字16進）で、同じ中身は1つだけ保管されます。
2. 取得の手順
   - 索引で選んだアーカイブ（決定0070で解決した名前・版）について、まずキャッシュに同じハッシュのファイルがあるか確認します。
   - なければ、取得元からキャッシュと同じフォルダー内の一時ファイルへコピーしながらSHA-256を計算します。
   - 索引の値と一致した場合だけ、一時ファイルを正式な名前へ一括で置き換えます（同じ名前が既にあれば一時ファイルを消します）。不一致・読み取り失敗・中断の場合は一時ファイルを消し、エラーにします。正式な名前のファイルが壊れた状態で現れることはありません。
3. 使用時の再検証: キャッシュのファイルを使うたびにSHA-256を再計算し、ファイル名と一致しない場合はそのファイルを使わずにエラーにします（手元での破損・改ざんの検出）。`aloe cache verify` で全ファイルを検査し、不一致のものを報告します（自動削除はしません）。
4. 同時実行: 置き換えが一括で行われ、同じ中身は同じ名前になるため、複数のビルドが同時に同じパッケージを取得しても安全です。一時ファイル名には一意な名前を使います。
5. オフライン: `--offline` を付けると、取得元へアクセスせずキャッシュだけを使います。必要なパッケージがキャッシュにない場合はエラーです。索引（`aloe-repo.json`）も、最後に取得したものをキャッシュに保存して使います。
6. 掃除: `aloe cache list` で一覧、`aloe cache clean` で全削除、`aloe cache clean --unused` で、ロックファイル・`package-db.json` から参照されていないものの削除ができます（参照の判定対象は指定したプロジェクト）。自動削除は行いません。
7. キャッシュは取得の高速化と取得元の切断時の継続のためのもので、導入先（`packages-dir`）と `package-db.json` への反映はP10で決めます。
