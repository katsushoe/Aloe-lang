Aloe 標準ライブラリ仕様（フィルタ編）

Draft • Japanese • Filters Library • version 40
この文書は Aloe 言語仕様書とは別個の「標準フィルタライブラリ仕様」です。

0. Overview（概要）

この文書では、Aloe 言語のうち「pipe<T> と filter」を前提とした 標準フィルタ群 を定義する。

言語仕様書本体は構文・型システム・pipe / filter 構文などを定義し、 本書はそれとは独立して「標準的に提供されるフィルタの名前・振る舞い・型」を記述する。

実装は、ここに定義されたシグネチャと意味論に「できるだけ忠実」であることを目標とするが、 性能・プラットフォーム差異などにより一部挙動が実装依存になる場合がある。

NOTE: ここでのコード例はすべて Aloe の擬似コードであり、 将来の言語仕様の変更に合わせて更新される可能性がある。
実装状況：本書のフィルター一覧はドラフトです。現行コンパイラーはユーザー定義filterを source | filter(name) | destination;、pipeline専用短縮構文を source |: name | destination; で呼び出せます。引数付き標準フィルターは source |: name: "argument" | destination; を使います。 型付きJSONデコーダーには source |: json: User | users; を使います。標準フィルターでは pipe<string> 用の tolower と toupper を実装し、カルチャーに依存しない不変カルチャーの大小文字変換を行います。さらに ltrim、rtrim、trim は各文字列の先頭、末尾または両端にあるUnicode空白を除去し、lineSplit は文字列チャンクをLFで分割してチャンク間の未完了行を保持します。camelcase、pascalcase、snakecase はUnicode空白で区切った単語を不変カルチャーで大小文字正規化し、適切な形式で連結します。startswith と contains は序数比較で一致する文字列を通し、strstr は引数を含む文字列だけを通して最初の一致位置以降を出力します。join は入力文字列を指定区切りで連結し、1つの文字列を出力します。空入力の場合も空文字列を1つ出力します。quote_meta は正規表現メタ文字をリテラルパターン用にエスケープします。utf8はbyte列全体をチャンク境界を維持して厳密にUTF-8復号し、文字列を1つ出力します（空入力は空文字列、不正byte列はVM例外）。VMはmd4、sha1、sha256をbyte列全体に対するハッシュfilterとして実装し、ハッシュ値の16、20、32byteを順番に出力します。MD4とSHA-1は旧式互換用途だけで使用し、セキュリティ用途には使用しないでください。VMは pipe<byte> に対応し、bin2hex は全byteを消費して大文字の16進文字列を1つ出力します。空入力では空文字列を出力します。 さらにbase64encodeはbyte列全体を標準Base64形式（改行なし）へ変換します。空入力では空文字列を出力します。base64decodeは入力文字列全体を連結して標準Base64を復号し、順番にbyteを出力します。空入力はbyteを出力せず、不正データはVM例外になります。 URL componentフィルターは以下のUTF-8 percent encode/decode規則を使用し、不正escapeまたは復号後の不正UTF-8はVM例外になります。htmlspecialcharsとhtmlspecialchars_decodeは以下の固定entity表記を実装しています。html_entity_decodeは認識できる名前付き・数値HTML文字参照を復号して未知の参照を保持し、生成文字列を再帰的に復号せず1回だけ処理します。markupのsanitizeは行いません。strip_tagsは文字列ごとに完結したcommentとmarkup風の区間を除去し、通常のless-than文字と未完了候補は保持します。VMはpipe<string[]>用のcsvenodeを実装し、3.2.1のCSVレコード規則に従います。csvdecodeも各入力文字列を独立したレコードとして解析し、不正レコードではVM例外になります。parse_strは各項目をフォーム形式でデコードしてmap<string, string>に変換し、number_format(spec)はpipe<decimal>を不変カルチャーの.NET decimal書式で整形します。このほか、限定サブセットとして sort、shuffle、json を実装しています。sortはpipe<int>および序数昇順のpipe<string>の引数なし形式と、宣言済みstructの直下のint keyを指定するsort: .Fieldをサポートします。条件・switch、他のsort key/要素型、archive、CRC32、対称暗号は未実装です。strip_tagsはHTML sanitizerではありません。また、uint32、BlowfishContext、AESContextを参照していますが、公開型としての契約は定義されていません。以下の例は概念例であり、現行コンパイラーでは実行できないものを含みます。

1. フィルタ共通ルール

1.1 呼び出し構文

本書に登場するフィルタは、すべて pipe<T> に対して filter(NAME ...) 形式で適用される。 

// 完全形
stdin
    | filter(utf8)
    | filter(lineSplit)
    | filter(trim)
    | stdout;

ただし、パイプライン文の中では filter キーワードを省略し、 |: NAME ... という糖衣構文を用いることができる。 

// 省略形（パイプライン専用構文）
stdin
    |: utf8
    |: lineSplit
    |: trim
    | stdout;

次の 2 つは等価である: 

stdin
    | filter(utf8)
    | filter(json: User);

stdin
    |: utf8
    |: json: User;

型引数が必要なものは、ラベル付き引数 として型を渡す: 

stdin
    |: utf8
    |: json: User
    | users;

1.2 型記法

本書では型を簡略化して記述する。例:

  • pipe<string> – 文字列のパイプ
  • pipe<byte> – バイト列のパイプ
  • pipe<T> – 型パラメータ付きのパイプ

1.3 副作用と例外

フィルタは次のような挙動を取ることがある:

  • 入力パイプをすべて消費してから出力を流す（例: sort, shuffle, zip）
  • 入力の一部だけを通す（例: if, startswith, contains）
  • 内部状態を持つ（例: 暗号コンテキスト付き AESencrypt）

フィルタがエラーに遭遇した場合の扱い（例外 / Result<T> の返却など）は、 各フィルタの説明で必要に応じて言及する。

1.4 名前空間（namespace）

標準ライブラリのルート名前空間は aloe とする。 すべての標準フィルタは、このルート配下の名前空間に属する。

  • 名前空間名はすべて小文字とし、区切りは . を用いる。
  • 例: aloe.text, aloe.encoding, aloe.crypto.hash など。

本書では、それぞれのフィルタに対して「正規の完全修飾名」として aloe.xxx.yyy 形式の名前空間を付与する。実際のコード中でのインポートや 省略形（短い名前のみでの利用）については、言語仕様側で定義される。

2. テキスト / エンコーディング

2.1 utf8

VM実装はbyte列全体を消費し、文字列を1つ出力します。入力チャンク境界をまたいでUTF-8を厳密に復号します。空入力では空文字列を出力し、不正なbyte列はVM例外になります。

名前空間 / シグネチャ

Namespace: aloe.encoding
filter utf8 : pipe<byte> -> pipe<string>

入力のバイト列を UTF-8 としてデコードし、文字列ストリームに変換する。

stdin
    |: utf8
    |: lineSplit
    | stdout;

2.2 lineSplit

名前空間 / シグネチャ

Namespace: aloe.text
filter lineSplit : pipe<string> -> pipe<string>

LF（\n）で分割し、直前のCR（\r）を取り除きます。空行は保持し、入力close時に残っている空でない行を出力します。末尾の改行の後に追加の空行は作りません。 

stdin
    |: utf8
    |: lineSplit
    |: trim
    | stdout;

3. JSON / データ変換

3.1 json（デコード）

名前空間 / シグネチャ

Namespace: aloe.json
filter json<T> : pipe<string> -> pipe<T>

各入力文字列を1件のJSONオブジェクトとして、int / bool / string フィールドだけを持つ struct T にデコードする。JSON名とフィールド名は大文字小文字を区別して完全一致し、 全フィールドを各1回必須とする。未知名、重複名、不足、型の不一致、不正JSONは入力番号と 可能ならフィールド名を含むエラーでフィルターを失敗させる。intには小数・指数表記を許可しない。数値・文字列の型変換、null、配列、 入れ子、enum、classは未対応。pipeline短縮構文で source |: json: User | users; のように型を渡す。 

stdin
    |: utf8
    |: json: User
    | users;    // pipe<User>

3.2 CSV 系: csvenode / csvdecode

3.2.1 csvenode

Namespace: aloe.csv
filter csvenode : pipe<string[]> -> pipe<string>

各文字列配列を、末尾の改行を付けずに1つのCSVレコードへエンコードします。 カンマ、二重引用符、CRまたはLFを含むフィールドは引用符で囲み、フィールド内の 二重引用符は2つにします。それ以外の内容は保持します。空配列は空レコードになり、 空文字列1つだけの配列は""と出力して区別します。

3.2.2 csvdecode

Namespace: aloe.csv
filter csvdecode : pipe<string> -> pipe<string[]>

入力文字列をそれぞれ1つのCSVレコードとして解析し、フィールドをstring配列で出力します。 カンマでフィールドを分け、引用符付きフィールドではカンマ、CR、LF、二重化した引用符を 使用できます。引用符なしフィールド内の引用符、閉じていない引用符付きフィールド、閉じ引用符と 次のカンマの間にある文字は不正としてVM例外になります。空レコードは空配列に、 ""は空フィールド1つに復号します。 レコードはpipeの各値ごとに処理し、引用フィールドの状態を値の間で引き継ぎません。 

stdin
    |: utf8
    |: lineSplit
    |: csvdecode
    | rows;   // pipe<string[]>

4. 条件分岐 / 並び替え

4.1 if / elseif / else

これらは「条件に応じて要素を通過させる」フィルタ群であり、1 つの複合フィルタとして解釈される。

名前空間 / シグネチャ（概念的）

Namespace: aloe.filter
filter if : pipe<T> -> pipe<T>
filter elseif : pipe<T> -> pipe<T>
filter else : pipe<T> -> pipe<T> 

users
    |: if:     .Age >= 20 and .Gender == Gender.Male
    |: elseif: .Age >= 13
    |: else
    | stdout;
  • if は最初の条件ブランチ。
  • elseif は追加の条件ブランチであり、直前が if または elseif の場合にのみ有効。
  • else は「どの条件にも一致しなかった要素」を通す最終ブランチ。

4.2 switch

Namespace: aloe.filter
filter switch : pipe<T> -> pipe<T>（詳細仕様は今後追加予定）

switch は、要素からキーを取り出し、その値に応じて複数の分岐に振り分けるフィルタである。 現時点では名前と役割のみ予約し、具体的な構文（case の書き方など）は今後の言語仕様側で定義する。

4.3 sort

決定0033により、引数なしの sort : pipe<byte> -> pipe<byte> に対応します。入力終了まで保持した後、元のbyte値を符号なし数値の昇順に出力し、件数と重複を保持します。空入力では値を出さず出力を閉じ、出力の容量制限とバックプレッシャーに従います。この範囲では引数と他の入出力型は受け付けません。

採用済み決定0026により、引数なしのsort : pipe<string> -> pipe<string>も実装します。入力終了後、カルチャーに依存しないUTF-16コード単位の序数昇順で安定ソートします。元文字列・重複・正規化形式を保持し、空文字列は先頭に並びます。空入力は値を出力せず、出力は容量制限とバックプレッシャーに従います。key指定・大小文字の同一視・正規化は行いません。

VMは引数なしのsort : pipe<int> -> pipe<int>を実装し、符号付きint32範囲外の値を拒否します。決定0025、0030、0035により、sort: .Fieldには宣言済みstruct直下のint、byteまたはstringフィールドを指定できます。名前は大文字小文字を区別して完全一致します。入力終了まで全要素を保持し、intキーは符号付きint32、byteキーは符号なし0〜255、stringキーはUTF-16コード単位の序数で安定昇順に並べます。元レコード・重複・同じキー内の入力順・文字列と正規化形式を保持し、大小文字の同一視や文化依存の比較は行いません。空入力は値を出さず出力を閉じます。出力は容量制限とバックプレッシャーに従い、バッファーメモリーは入力件数に比例します。他のキー型、入れ子のpath、式指定は拒否します。

キー指定のAloeBCスキーマは、intキー用の従来の3プロパティtypeName・fieldName・fieldIndexとの互換性を維持します。任意のfieldTypeはint、byteまたはstringだけを受け付け、コンパイラーはbyteまたはstringキーにそれぞれfieldType:byteまたはfieldType:stringを追加します。不正なスキーマとレコード・キーの型不一致は拒否します。

名前空間 / シグネチャ

Namespace: aloe.collection
filter sort : pipe<T> -> pipe<T>
filter sort(key) : pipe<T> -> pipe<T>

入力要素をソートして出力する。内部で全要素を一度バッファし、ソート後に順番に流す。 

users
    |: sort: .Age   // 年齢で昇順ソート
    | stdout;

4.4 shuffle

採用済み提案0023に基づき、VMは引数なしのshuffle : pipe<int> -> pipe<int>を実装しています。入力終了まで全要素を保持し、非暗号学的なSystem.Random.Sharedを使うFisher-Yatesで並べ替え、出力pipeの空きを待ちながら全要素を出力します。件数と重複を保持し、空入力は値を出さずに終了します。入力と同じ順序も正当な結果です。seed・決定的再現・乱数状態の永続化・暗号学的予測困難性は保証しません。採用済み提案0028により、同じ処理をpipe<string>にも適用し、元文字列の内容・件数・重複を厳密に保持します。正規化と型変換は行いません。決定0034によりpipe<byte>にも同じ処理を適用し、byte値・件数・重複を保持します。他の要素型と引数は拒否します。メモリは入力件数に比例し、完了時にバッファを解放します。交換操作ごとに協調スケジューラーへ制御を戻します。pipeの容量制限は全体のバッファ容量を制限しません。秘密情報の生成には使用しないでください。

Namespace: aloe.collection
filter shuffle : pipe<T> -> pipe<T>

要素の順序をランダムに並び替える。内部で全件をバッファしてから乱択して出力する。 

cards
    |: shuffle
    | gameDeck;

5. 暗号 / ハッシュ / バイナリ

5.1 ハッシュ: md4 / sha1 / sha256

VMは pipe<byte> 用のmd4、sha1、sha256を実装しています。入力全体を蓄積せずに逐次処理し、入力pipeのclose後にdigest byteを順番に出力します（MD4は16個、SHA-1は20個、SHA-256は32個）。空入力では空メッセージの標準digestを出力します。MD4とSHA-1は旧式システムとの相互運用だけを目的とし、新しいセキュリティ用途には適しません。新規用途ではSHA-256を使用してください。

Namespace: aloe.crypto.hash
filter md4 : pipe<byte> -> pipe<byte>
filter sha1 : pipe<byte> -> pipe<byte>
filter sha256 : pipe<byte> -> pipe<byte>

入力全体のハッシュ値を計算し、そのハッシュバイト列を出力する。 新しいセキュリティ用途のhashには sha256 または用途の基準で承認された現行アルゴリズムを使用してください。md4 はlegacy用途に限られ、RFC 6150でHistoric扱いとなりました。NISTは暗号保護用途のSHA-1を2030年12月31日までに移行する方針です。新規用途では sha1 も互換性用に限ってください（NISTの移行計画）。 

stdin
    |: sha256
    |: bin2hex
    | stdout;

5.2 バイト列変換: bin2hex / crc32

5.2.1 bin2hex

Namespace: aloe.encoding
filter bin2hex : pipe<byte> -> pipe<string>

入力byte列全体を消費し、大文字の16進文字列を1つ出力します。空入力では空文字列を出力します。

5.2.2 crc32

Namespace: aloe.crypto.hash
filter crc32 : pipe<byte> -> pipe<uint32>

入力全体の CRC32 値を計算し、1 つの整数として出力する。

5.3 Base64 / URL

実装済みのURLフィルターはRFC 3986のURI component規則を使います。UTF-8 byte列のうち非予約文字 A-Z a-z 0-9 - . _ ~ 以外を大文字の %HH で符号化します。空白は %20、プラス記号は文字として扱い、フォーム形式の空白には変換しません。不正なescapeと不正UTF-8は拒否します。

実装済みのencoderはbyte列全体を消費し、改行なしの標準Base64文字列を1つ出力します。decoderは文字列全体を連結して復号し、順番にbyteを出力します。空入力はencoderが空文字列を、decoderがbyteなしを返し、不正データはVM例外になります。

実装済みのbase64encodeはbyte列全体を消費し、改行なしの標準Base64文字列を1つ出力します。空入力では空文字列を出力します。

Namespace: aloe.encoding
filter base64encode : pipe<byte> -> pipe<string>
filter base64decode : pipe<string> -> pipe<byte>

Namespace: aloe.net.http
filter urlencode : pipe<string> -> pipe<string>
filter urldecode : pipe<string> -> pipe<string> 

fileBytes
    |: base64encode
    | stdout;

// ...

stdin
    |: base64decode
    | fileBytes;

5.4 共通暗号: Blowfish / AES

5.4.1 Blowfish: blowfishencrypt / blowfishdecrypt

Namespace: aloe.crypto.cipher
filter blowfishencrypt(ctx: BlowfishContext) : pipe<byte> -> pipe<byte>
filter blowfishdecrypt(ctx: BlowfishContext) : pipe<byte> -> pipe<byte>

コンテキスト ctx に鍵・IV・モード等を保持し、それに従って暗号化／復号を行う。

5.4.2 AES: AESencrypt / AESdecrypt

Namespace: aloe.crypto.cipher
filter AESencrypt(ctx: AESContext) : pipe<byte> -> pipe<byte>
filter AESdecrypt(ctx: AESContext) : pipe<byte> -> pipe<byte>

AES (CBC / GCM など) による暗号化／復号を行う。具体的なモードやパディングは AESContext の定義に依存する。

6. 文字列ユーティリティ

6.1 大文字・小文字変換: tolower / toupper

Namespace: aloe.text
filter tolower : pipe<string> -> pipe<string>
filter toupper : pipe<string> -> pipe<string> 

lines
    |: tolower
    | normalized;

6.2 ケース形式変換: camelcase / pascalcase / snakecase

Namespace: aloe.text
filter camelcase : pipe<string> -> pipe<string>
filter pascalcase : pipe<string> -> pipe<string>
filter snakecase : pipe<string> -> pipe<string>

  • camelcase: "hello world" → "helloWorld"
  • pascalcase: "hello world" → "HelloWorld"
  • snakecase: "Hello World" → "hello_world"

単語はUnicode空白で区切り、前後および連続する空白は無視します。各単語を不変カルチャーで大小文字正規化します。

6.3 部分一致フィルタ: startswith / contains / strstr

Namespace: aloe.text
filter startswith(prefix: string) : pipe<string> -> pipe<string>
filter contains(needle: string) : pipe<string> -> pipe<string>
filter strstr(needle: string) : pipe<string> -> pipe<string>

  • startswith: 序数比較で prefix から始まる行だけを通す。
  • contains: 序数比較で needle を含む行だけを通す。
  • strstr: 序数比較で needle を含む行だけを通し、最初に一致した位置以降のサブ文字列を返す（PHP の strstr に類似）。
lines
    |: startswith: "[ERROR]"
    |: strstr: "detail="
    | stdout;

6.4 トリム / 結合: ltrim / rtrim / trim / join

Namespace: aloe.text
filter ltrim : pipe<string> -> pipe<string>
filter rtrim : pipe<string> -> pipe<string>
filter trim : pipe<string> -> pipe<string>
filter join(sep: string) : pipe<string> -> pipe<string>

ltrim、rtrim、trimは各入力文字列の先頭、末尾または両端にあるUnicode空白を除去します。

join は、入力の全ての文字列を sep で結合し、1 つの文字列として出力します。入力が空の場合は空文字列を1つ出力します。 

lines
    |: trim
    |: join: "\n"
    | text;

7. アーカイブ / 圧縮 / CSV

7.1 ZIP / TAR: zip / unzip / tar

Namespace: aloe.archive
filter zip : pipe<byte> -> pipe<byte>
filter unzip : pipe<byte> -> pipe<byte>
filter tar : pipe<byte> -> pipe<byte>

ここでは「ストリーム全体を 1 つのアーカイブとして扱う」単純なモデルを想定する。 複数エントリの操作やファイル名などの詳細は、別途高レベル API として定義しうる。 

stdin
    |: zip
    | stdout;

// ...

stdin
    |: unzip
    | stdout;

8. HTML / サニタイズ

8.1 エスケープ / 逆変換

VMのhtmlspecialcharsは&、<、>、"、'を&amp;、&lt;、&gt;、&quot;、&#39;へ変換します。htmlspecialchars_decodeはこのcanonical表記のみを戻し、入れ子entityを二重にdecodeしないよう&amp;を最後に処理します。これらは文字のescapeであり、HTML markupのsanitizeではありません。html_entity_decodeは入力文字列ごとに認識できる名前付き・数値HTML文字参照を復号し、未知の参照をそのまま残し、生成文字列を再帰的に処理せず1回だけ復号します。markupのsanitizeではありません。strip_tagsはASCII英字で始まるtag名のmarkup風区間とcommentを除去し、属性内の引用符付き>を終端扱いしません。2 < 3などの通常文字列と未完了候補は保持します。処理単位はpipeの各文字列で、chunkをまたいでtag stateを保持しません。script/style内部は周囲のtagのみ除去してテキストを残します。HTML sanitizerやセキュリティ境界ではありません。

Namespace: aloe.html
filter htmlspecialchars : pipe<string> -> pipe<string>
filter htmlspecialchars_decode : pipe<string> -> pipe<string>
filter html_entity_decode : pipe<string> -> pipe<string>
filter strip_tags : pipe<string> -> pipe<string>

  • htmlspecialchars: <, >, &, " などを安全なエンティティに変換。
  • htmlspecialchars_decode: 上記の逆変換。
  • html_entity_decode: より広い HTML エンティティ（例: &nbsp; 等）を実体化。
  • strip_tags: 各文字列の完結したcommentとmarkup風区間を除去します。残りの文字列をsanitizeしません。
htmlLines
    |: strip_tags
    |: trim
    | plainText;

9. パース / フォーマット

9.1 クエリ文字列: parse_str

Namespace: aloe.net.http
filter parse_str : pipe<string> -> pipe<map<string, string>>

入力1件ごとにクエリ文字列をパースしてマップを出力します。区切りは &、最初の = がキーと値を分け、 = のない項目の値は空文字です。空セグメントは無視し、空キーは許可します。同じキーが複数回現れた場合は最後の値を保持します。 値はフォーム形式でデコードし、+ は空白、%HH バイト列は厳密なUTF-8として扱います。不正なエスケープまたはUTF-8はVM例外になります。 空入力は空マップを出力します。リテラルのプラス記号を保持するRFC 3986準拠の urldecode とは動作が異なります。

9.2 数値フォーマット: number_format

Namespace: aloe.number
filter number_format(spec: string) : pipe<decimal> -> pipe<string>

各decimal値を文字列へ変換する。書式文字列 spec の形式は実装依存ですが、 例として "#,##0.00" を使用できます。現在のVMは.NET decimalのカスタム数値書式を不変カルチャーで評価し、 無効な書式ではVM例外を発生させます。パイプの順序を保ち、通常の有界出力バックプレッシャーに従います。

9.3 正規表現向けエスケープ: quote_meta

Namespace: aloe.text
filter quote_meta : pipe<string> -> pipe<string>

正規表現エンジンのメタ文字をエスケープし、安全にリテラルとして扱えるようにします。このフィルターは pipe<string> 用に実装済みです。 

patterns
    |: quote_meta
    | safePatterns;

本書に列挙されていないフィルタは、ユーザー定義フィルタまたは外部ライブラリとして自由に追加できる。 ここで定義した名前は「Aloe 標準フィルタ」として予約され、互換実装間での共通 API として機能することを意図している。
